# CLAUDE.md

Инструкции для AI-сессий (Claude Code) в репозитории `aiCostTracker`. Эти
инструкции имеют приоритет над поведением по умолчанию — следуй им точно.

## Что это за репозиторий

`aiCostTracker` (бинарник `aicost`) — CLI-инструмент на **Go**, агрегирующий
расходы и использование по нескольким AI-провайдерам (Anthropic, OpenAI и далее)
в один локальный дашборд в терминале. Соло pet-проект с приоритетом **обучения
Go**; реализация ведётся AI-ассистентом. Не бизнес — экономическая
целесообразность не требуется. Расходы ≈ **$0/мес** (чистый CLI, без сервера;
обращения к provider usage API — только по команде). История расходов хранится
локально в SQLite для трендов по времени. Без телеметрии.

Полное видение — [`docs/PLAN.md`](docs/PLAN.md); технический план и разбивка по
Этапам — [`docs/TECHNICAL_PLAN.md`](docs/TECHNICAL_PLAN.md); за пределами MVP —
[`docs/POST_MVP_PLAN.md`](docs/POST_MVP_PLAN.md).

## Структура репозитория

| Путь | Содержимое |
|---|---|
| `docs/` | `PLAN.md`, `TECHNICAL_PLAN.md`, `POST_MVP_PLAN.md` |
| `.claude/skills/go-cost-tracker-dev/SKILL.md` | Конвенции написания кода именно этого проекта |
| `cmd/aicost/main.go` | Тонкий `main` — build-метаданные, отмена по сигналу, вызов `cli.Execute` |
| `internal/cli/` | Сборка команд (`report`, `history`, `version`) |
| `internal/config/` | Загрузка конфига + env; admin-ключи провайдеров |
| `internal/provider/` | **Порт `ProviderUsageSource`** + адаптеры `anthropic.go`, `openai.go` (…и далее) |
| `internal/storage/` | Порт `Store` (SQLite + in-memory fake); снапшоты истории |
| `internal/report/` | Агрегация записей + рендер таблицы |

`pkg/` намеренно нет — всё ядро в `internal/`. Docker/Compose нет и не
планируется (чистый CLI; обоснование — `TECHNICAL_PLAN.md §7`).

## Ключевые архитектурные решения (не переоткрывай без причины)

- **Порт-адаптер `ProviderUsageSource`** — разные usage-API провайдеров спрятаны
  за единым интерфейсом; добавить провайдера = один файл-адаптер (SKILL §2).
- **admin/org-ключ ≠ ключ модели** — usage-API требуют отдельного admin-ключа;
  поле конфига `admin_key`, не путать с ключом вызова моделей.
- **Точные эндпоинты провайдеров не выдуманы** — помечены `[ASSUMPTION]`/
  `[TODO уточнить в Этапе 1]` (`TECHNICAL_PLAN.md §4`), проверяются по живой
  документации в Этапе 1. Не хардкодить несуществующие URL как факт.
- **HTTP — ручной `net/http` без SDK**, retry с экспоненциальным backoff+jitter
  (паттерн из `gitl`); admin-ключ никогда не логируется.
- **SQLite для локальной истории** — ради трендов по времени, не только текущего
  среза; `Save` — идемпотентный upsert.

## Dev-workflow (обязательный процесс на каждый этап/задачу)

Главная ветка — **`master`**.

1. Opus 4.8 — если требуется детальное планирование этапа — планирование, затем написание кода.
2. Sonnet — проверка качества покрытия тестами, тестирование, проверка работоспособности, проверка покрытия новых функций.
3. Opus — независимое ревью: skill /code-review на diff ветки, фиксируем замечания.
4. Цикл исправлений — до 3 итераций: Sonnet правит замечания → тесты снова.
5. Commit + push + PR — conventional-commit с русским subject, PR в master-ветку.

Коммить/пуш только когда этап завершён (или пользователь явно попросил).

## Команды разработки

```bash
export PATH="$HOME/sdk/go/bin:$PATH"   # если go не находится

go build ./...                 # сборка (зелёная с Этапа 0)
go vet ./...                   # статический анализ
go test ./...                  # тесты
go test -race ./...            # где есть конкурентность
gofmt -l .                     # проверка форматирования (пусто = ок)

go run ./cmd/aicost --version  # build-метаданные
go run ./cmd/aicost            # usage (в Этапе 0 — заглушка)
# Этап 1+: go run ./cmd/aicost report --period=...
```

Перед коммитом кода: `go build ./...`, `go vet ./...`, `go test ./...` должны
проходить; желателен `gofmt`.

## Конвенции проекта

- **Язык:** документация и subject коммитов — **на русском**; код, идентификаторы
  и комментарии в коде — на английском.
- **Коммиты:** conventional-commit с русским subject, напр.
  `feat(provider): реализовать адаптер OpenAI usage API`. Заканчивать трейлером
  `Co-Authored-By: Claude`.
- **Ветки:** feature-ветки от `master`; PR в `master`.
- **Секреты:** admin-ключи только локально (конфиг/env), никогда в git/логах/выводе.
- Детальные конвенции написания кода — в
  [`.claude/skills/go-cost-tracker-dev/SKILL.md`](.claude/skills/go-cost-tracker-dev/SKILL.md).
