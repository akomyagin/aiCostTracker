## Решения, которые стоит помнить (не всегда очевидны из кода)

- **Gemini отложен осознанно, не забыт.** Проверено по живой документации:
  у Gemini API нет программного cost-API вообще; у Vertex AI единственный
  путь — экспорт биллинга в BigQuery (SQL-запросы, не REST GET;
  service-account+OAuth2 вместо `admin_key`-строки; бэкфилл до 5 дней). Это
  другой класс интеграции, а не файл-адаптер по образцу остальных. Детали —
  `docs/POST_MVP_PLAN.md` §P1, блок «Google Gemini» (строки ~44–72).
- **Миграция SQLite (Этап 9) полностью молчаливая** — при открытии БД со
  старой схемой (`cost_usd REAL`) она пересобирается в `cost_micros INTEGER`
  без единой строки вывода пользователю. Это осознанно (единичное разовое
  событие, в проекте вообще нет логгера — см. ниже), задокументировано как
  известное ограничение в `docs/POST_MVP_PLAN.md §P5`, не баг.
- **В проекте нет `log/slog`/`--verbose`** — при аудите обнаружилось, что
  `TECHNICAL_PLAN.md` и `PLAN.md` описывали логгер, которого никогда не было
  в коде (видимо, унаследовано из шаблона `gitl`). Поправлено на «пока нет
  отдельного логгера» — вывод только stdout/stderr. Если кто-то захочет
  «починить» это упоминание обратно — не надо, это была фактическая ошибка
  доков, а не пропущенная фича.
- **`config.Alert.MonthlyUSD` осознанно остался `float64`**, а не `int64`
  micros, хотя вся остальная денежная арифметика мигрировала — это
  вводимое пользователем число, не накапливаемая сумма, конвертируется в
  micros один раз при каждом сравнении (`cli.checkAlert`). Не «доделывать».
